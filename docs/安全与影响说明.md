# 安全与影响说明

本页把 vhm 会改什么、不会改什么、如何回滚汇总在一处，内容与 README 各功能章节一致。第一次使用前建议先读完本页，再从只读体检开始。

## 只读操作（不修改任何文件）

以下功能只查看、不修改：安全体检 `[02]`、SSH 状态、端口一览、用户列表、登录记录，以及只读子命令 `checkup`、`ports`、`ssh-status`、`vw-status`、`vw-users`、`changes`、`diagnose`、`deps`、`version`。

## 会修改的文件与配置

| 对象 | 路径 / 方式 | 说明 |
|---|---|---|
| 实例配置 | `/etc/vaultwarden-hardening.conf` | 权限 `600` |
| SSH 配置 | `/etc/ssh/sshd_config.d/00-vhm.conf`、`/etc/ssh/sshd_config` | 端口等全局设置写 drop-in；登录方式和 root 登录开关放在主配置末尾各自的 `Match User` 中，不新增全局 `Include` |
| SSH 登录验证 | `/etc/pam.d/sshd`、`vhm-ssh-user-<用户>`、`vhm-access-ssh-legacy` | 每用户独立子栈；未选用户继续使用原 auth 栈，保留 account / session |
| 登录配置状态 | `/var/lib/vaultwarden-hardening/ssh-profiles.json`、`access.conf` | 分用户登录方式、root 登录开关与可选管理员方案状态，纳入回滚 |
| 登录公钥 | `/etc/ssh/vhm-authorized-keys/<用户>` | root 所有、`644`；仅是公钥，sshd 可读取 |
| 2FA 绑定 | `/etc/security/vhm-access/<用户>/totp` | root 所有、`600`，父目录 `700`；旧 root 模式仍使用 `/root/.google_authenticator`（`400`） |
| 可选 sudo 双项验证 | `/etc/pam.d/sudo`、`sudo-i`、`vhm-access-sudo`、`/etc/sudoers.d/99-vhm-access` | 只为所选管理员添加 TOTP 和零缓存要求，不扩大命令授权；不写全局 common-auth |
| Fail2Ban | `/etc/fail2ban/jail.d/vhm-sshd.local` | 写独立文件，不修改系统自带文件 |
| 后台服务 | `/etc/systemd/system/vhm-ssh-port-sync.{service,path,timer}`、`vhm-guard-boot.service` | Fail2Ban 端口同步与开机回滚；进入菜单时按当前版本与项目位置刷新 |
| 日志轮转 | `/etc/logrotate.d/vaultwarden-hardening` | `run.sh` 安装 |
| 防火墙 | 1Panel iptables 的 `1PANEL_BASIC` 链与 1Panel 规则文件 / UFW 命令 | 与 1Panel 页面读写同一套规则，立即生效且持久保存 |
| 内核参数 | `/etc/sysctl.d/90-vhm-hardening.conf` | 写独立文件 |
| Vaultwarden 设置 | `<数据目录>/config.json` | 原子写入，权限 `600` |
| 1Panel 设置 | 全部通过 `1pctl` 完成 | 不直接修改 1Panel 数据库 |
| 变更记录 | `/var/lib/vaultwarden-hardening/changes/` | 保存修改前的文件、权限和属主 |
| 日志 | `/var/log/vaultwarden-hardening.log` | 以 `600` 权限创建；已脱敏，不输出令牌、哈希、密码 |

## 明确不会做的事

- 不使用 `nullok`：没有绑定动态口令就无法登录，不留「没绑定就跳过」的后门。
- 不修改 `ip_forward`。
- 不修改 Fail2Ban 系统自带文件，只写自己的 `jail.d` 文件。
- 不绕过 1Panel 直接修改其数据库。
- 不提供卸载和数据恢复功能。
- 自动安全更新不升级容器和 1Panel 应用，也不自动重启系统。

## 修改前的保护

- 所有会修改系统的操作都会先显示要改什么，再要求输入 `yes`（大小写不敏感），其他输入即取消。
- 修改 Vaultwarden 设置前，先调用兄弟项目 vbm 做一次完整备份；本地校验、服务恢复、远端核验全部通过才继续。未安装 vbm 时会额外要求确认，并仍保存修改前的 `config.json`。
- 修改 SSH 端口、登录方式或重新绑定正在使用的动态口令时：先保存原配置并启用 5 分钟定时器与 `vhm-guard-boot.service`，两项保护都成功后才写入。写入 SSH 配置后执行 `sshd -t` 并用 `sshd -T` 核对生效值；重载后保持当前会话，另开窗口按新方式登录成功后输入 `yes`。确认状态保存后才停定时器；取消会立即尝试回滚，超时或中断时由定时器接手，重启时由开机服务接手。如果之后又有改过同一文件的变更，则停止自动回滚，通过 VNC 登录后在 [25] 检查。改端口时先同时监听新旧端口，确认新端口能登录后再关闭旧端口。
- 可选普通管理员方案在一笔受保护变更中完成：先配置该用户三项登录与 sudo 双项认证，保留 root 原认证路径；必须从本阶段开始后的新 SSH 连接直接执行向导给出的 `sudo vhm access-verify`，并回原窗口确认，才关闭 root SSH。随后再次新建连接执行最终验证。两阶段共享同一个保护截止时间，取消或超时会恢复 SSH、PAM、sudoers、公钥、种子和元数据。退出方案要回滚原迁移，活动迁移记录受保护，不自动删除。
- 源码更新：启动检查和 `[27]` 手动检查都会先展示当前版本、目标版本及目标提交新增的更新日志；没有新增日志时显示提交摘要。输入 `yes` 才快进到已预览的提交，旧 `AUTO_UPDATE=apply` 也需要确认。`AUTO_UPDATE=off` 只跳过启动检查；`UPDATE_REQUIRE_SIGNED=1` 只接受签名校验通过的目标提交。这些选项只控制 vhm 自身的源码更新，与 Linux 软件包的自动安全更新独立。
- Fail2Ban 配置先经 `fail2ban-client -t` 检查，启动失败自动恢复原配置。

## 回滚

- `[25]` 列出最近 30 条变更，可按条回滚；命令行可用 `vhm rollback <变更ID>`。回滚失败会标记为「回滚失败」并保留记录，修复原因后可以重试；重试前不要删除记录。
- 回滚登录配置时，若较新的变更修改过同一个 SSH、PAM 或认证文件，先处理更新的记录。旧快照不会直接覆盖后来为其他账号设置的规则。
- Vaultwarden 回滚只处理当前选中实例的记录。若记录属于另一实例，先核对 `VW_DATA_DIR`，切回原实例后再重试。
- 变更记录自动保留最近 50 条以及 90 天内的全部记录；防锁死保护中的记录不会被自动删除。
- 1Panel 修改用户名 / 密码（不保存旧值）和应急重置 `[14]` 不能回滚。UFW 删除回滚也要求能核对原位置和删除后的规则顺序；不能安全恢复时需人工处理。

## 应急入口

- 修改 SSH 前请先打开 VPS 服务商控制台的 VNC，它是最后的应急入口，不受 SSH 配置影响。
- 2FA 应急码请离线保存；手机丢失且应急码用完时，只能通过 VNC 恢复。
- `timestamp_timeout=0` 约束每次新的 sudo 提权调用。已经打开的 root shell、`sudo` 启动的解释器或 vhm 菜单会继续持有 root 权限，不会对内部操作逐条认证。sudo 自身的帮助、版本和某些无需提权的调用也不会要求认证。
- SSH / sudo 共用同一用户的动态口令时，不允许重用已经接受的验证码；立即提权请等待下一组，或使用一个未用过的应急码。

## 验证记录

自动化测试用临时目录和模拟命令检查 SSH 保护、变更记录和 systemd 单元生成，并在 Debian 12 和 Ubuntu 24.04 容器中验证真实的 SSH、PAM 和 sudo 行为。带 systemd 的 VNC 真机重启演练尚待记录。演练时请使用带快照和控制台的测试机，记录发行版、OpenSSH、1Panel、Vaultwarden 版本和日期，以及开机日志、`[25]` 状态和新 SSH 会话结果；分别核对未确认的变更会回滚、已确认的变更会保留。
