# vhm 使用手册

适用版本：0.1.x。本工具只审计并加固 **1Panel 应用商店安装的 Vaultwarden**，与备份工具 `vbm` 配合使用。

## 1. 安装

### 1.1 要求
- Linux + systemd，root 权限。
- 依赖：`docker flock sed awk stat sha256sum python3 curl`；推荐 `ss`（iproute2）、`git`。用 `vhm deps` 或菜单 `[02]` 检查。
- 仓库路径上的**每一级目录**都必须 root 所有且他人不可写（`run.sh` 会逐级检查），因此放在 `/opt` 下：

```bash
sudo git clone https://github.com/OmenTwwnmfm/vaultwarden-1panel-hardening-manager /opt/vaultwarden-1panel-hardening-manager
sudo bash /opt/vaultwarden-1panel-hardening-manager/run.sh
```

`run.sh` 会安装 `/usr/local/bin/vhm`（重复运行即修复），然后进入菜单。

### 1.2 与 vbm 共存
- 若存在 `/etc/vaultwarden-backup.conf`，vhm **只读**复用其中的 `VW_DATA_DIR` 作为实例身份。
- vbm 记录的目录找不到对应容器时，vhm 直接停止，不会猜测。
- vhm 不做备份；D-01 只检查 vbm 是否安装、状态是否正常。

## 2. 配置 `/etc/vaultwarden-hardening.conf`

由 `[01]` 从样例生成，权限 600。`KEY="值"` 每行一项。

| 键 | 默认 | 说明 |
|---|---|---|
| `VW_DATA_DIR` | 空=自动识别 | 容器 `/data` 的主机路径，即实例身份。多实例时必须填写 |
| `VW_CONTAINER` | 空=自动识别 | 容器名；填了 `VW_DATA_DIR` 时也建议一并填写 |
| `VW_DOMAIN` | 空 | 对外域名（不带协议），S-01 用它读取 `https://<域名>/api/config` 的版本 |
| `EXTERNAL_PROBE_URL` | 空 | 外部探测地址，见 §5 |
| `NOTIFY_TELEGRAM_TOKEN` / `NOTIFY_TELEGRAM_CHAT` | 空 | 两项都填才发送 |
| `NOTIFY_NTFY_URL` | 空 | 例如 `https://ntfy.sh/<主题>` |
| `NOTIFY_WEBHOOK_URL` | 空 | POST `{"text": "..."}` |
| `WATCH_ONCALENDAR` | `daily` | systemd `OnCalendar` 语法，如 `*-*-* 03:30` |

实例识别规则：扫描所有挂载了 `/data` 且镜像名含 `vaultwarden` 的容器。0 个或多于 1 个候选都会停止（退出码 2），并列出候选。

## 3. 菜单与子命令

| 菜单 | 子命令 | 作用 |
|---|---|---|
| [01] | — | 生成配置、创建状态目录、识别实例并写回配置 |
| [02] | `vhm deps` | 依赖与环境检查 |
| [03] | `vhm audit` | 全量只读审计 |
| [04] | `vhm audit --domain <域>` | 按域审计：panel/exposure/app/container/host/data/supply |
| [05] | `vhm report show` | 查看最新报告（Markdown） |
| [06] | `vhm report export [目录]` | 导出最新 JSON + Markdown 报告（600） |
| [07] | `vhm plan` | 由最新报告生成计划 |
| [08] | `vhm plan --diff` | 计划 + 可自动项的具体 chmod 差异 |
| [09] | `vhm apply` | 仅执行 `mode=auto` 条目（需输入 yes） |
| [10] | `vhm rollback [--snapshot 目录] [--yes]` | 回滚到快照（默认最新） |
| [11] | `vhm rollback --list` | 列出快照 |
| [12]–[15] | — | 打印指引：1Panel 面板、OpenResty 片段、Vaultwarden 参数、主机/SSH |
| [16] | `vhm watch install` | 同步后台脚本并安装定时巡检 |
| [17]/[18]/[19] | `vhm watch status/pause/resume` | 巡检状态、暂停、恢复 |
| [20] | `vhm watch notify-test` | 发送测试通知 |
| [21] | `vhm diagnose` | 脱敏诊断，可直接贴进 Issue |
| [22] | `vhm watch install --sync-only` | 只同步后台脚本 |
| [23] | — | 工作区干净时快进更新源码 |

菜单编号自 v0.1.0 起冻结，后续只追加不改号。

**退出码**：`0` 成功 · `1` 失败/取消 · `2` 实例无法确定 · `75` 另一个 vhm 任务正在运行（已跳过）。

## 4. 标准流程

### 4.1 审计
```bash
sudo vhm audit
# [信息] 审计实例 vaultwarden（/opt/1panel/apps/vaultwarden/vaultwarden/data）
# 评级 C：通过 14 失败 3 警告 3 未知 2
```
- 审计不修改任何被审计对象，只在 `/var/lib/vaultwarden-hardening/reports/` 写报告（600），`latest.json`/`latest.md` 指向最新一份。
- 评级：任一 P0 失败为 **D**；否则按 fail/warn 扣分（P0=10、P1=4、P2=1），0 分为 A，≤4 为 B，其余为 C。`unknown` 不扣分，但要人工确认。
- 应用配置的取值顺序：`config.json`（/admin 页面保存的设置）→ 容器环境变量 → Vaultwarden 默认值。

### 4.2 计划
```bash
sudo vhm plan --diff
# [P1] D-02 (host/auto)
#   当前：/opt/.../data/db.sqlite3-wal:644
#   操作：自动：chmod o-rwx 数据目录及关键文件
# ---- 可自动项差异 ----
# chmod /opt/.../data/db.sqlite3-wal: 644 -> 640
```
- `owner=1panel` 的条目**只给面板操作路径**，需要你在 1Panel 里手动改。原因是 1Panel 升级或重建时会覆盖这些配置。
- 计划写入 `plan.json`/`plan.txt`。全部通过时计划为空，重复生成结果一致。

### 4.3 应用
```bash
sudo vhm apply      # 输入 yes 确认
```
执行顺序：
1. 记录敏感路径的权限和属主快照到 `snapshots/<时间>-<PID>/perms.tsv`，并生成 `SHA256SUMS`。
2. 执行 `chmod o-rwx`。
3. 健康闸门：每 2 秒执行一次容器内 `/healthcheck.sh`，连续 2 次成功即通过，120 秒内未通过即判失败。
4. 失败时自动回滚到第 1 步的快照，并返回 1。

当前只有 D-02 一项可自动修复，它不触及容器，所以不调用 vbm 备份。

### 4.4 回滚
```bash
sudo vhm rollback --list
sudo vhm rollback --snapshot /var/lib/vaultwarden-hardening/snapshots/20261123-203000-1234
```
快照校验和不一致时拒绝回滚。已不存在的路径会跳过并给出警告。

### 4.5 记录决策
对暂不修复的项（如家里人需要 Send 功能），用 [加固决策记录模板](加固决策记录模板.md) 记下理由和补偿措施。

## 5. E-03 外部探测约定

本机无法证明 `/admin` 从公网是否可达，需要一个位于**外部网络**的探测服务：
- vhm 对 `EXTERNAL_PROBE_URL` 发起 GET 请求，响应体**只能包含一个 3 位 HTTP 状态码**（允许前后空白），即外部访问 `https://<域名>/admin` 得到的状态码。
- 判定：`2xx`/`3xx` → fail（可达）；`4xx` → pass（已拦截，如 403）；`5xx`、格式不对、请求失败 → unknown。

示例：在另一台机器上用 cron 定期执行下面的命令，把结果写到静态文件，再把该文件的地址填为 `EXTERNAL_PROBE_URL`：
```bash
curl -s -o /dev/null -w '%{http_code}' https://vault.example.com/admin > /var/www/probe/vault-admin.txt
```

## 6. 定时巡检与通知
- `[16]` 先把脚本同步到 `/usr/local/lib/vaultwarden-hardening/scripts`，再安装 `vaultwarden-hardening-watch.timer`（`Persistent=true`，随机延迟 10 分钟）。巡检使用这份副本，所以**更新源码后要执行 `[22]`**。
- 每次巡检做一次全量审计，只有出现**新增**的 fail 项时才通知；已知的失败项不会重复通知。
- 通知失败只记警告，不影响巡检结果。通知 URL（含 Telegram token）经标准输入传给 curl，不会出现在 `ps` 中。
- 与手动操作冲突时（锁被占用），巡检以 75 退出，systemd 视为成功。
- 日志：`/var/log/vaultwarden-hardening.log`（已脱敏）。仓库里的 `logrotate-vaultwarden-hardening` 可复制到 `/etc/logrotate.d/`。

## 7. 安全与隐私
- 报告、诊断、日志中的 `*_TOKEN`/`*_PASSWORD`/`*_SECRET`/`*_KEY` 值、argon2 哈希、40 位以上随机串都会被替换为 `***REDACTED***`/`***ARGON2***`/`***LONG***`；路径与 URL 保留原样。
- ADMIN_TOKEN 只记录类型（argon2/明文）和长度，从不记录值。
- 配置文件和报告权限均为 600，状态目录为 700。

## 8. 常见问题

**发现多个候选实例？** 在配置中填写 `VW_DATA_DIR`（和 `VW_CONTAINER`），然后重新执行 `[01]`。

**在 /admin 里改了设置，审计结果却没变？** 审计优先读 `config.json`。反过来，只改 1Panel 应用参数（环境变量）而 `config.json` 里有旧值时，旧值仍然生效，需要在 /admin 中修改或删除对应项。

**1Panel 升级或重建应用后配置丢了？** 1Panel 会重新生成 compose 和应用参数。升级后请重新审计，并按计划在面板中恢复设置。漂移检测尚未实现。

**P-01/P-02 显示 unknown？** 说明没找到 `1pctl`，或者它的输出格式和预期不一致。请把 `[21]` 诊断结果和脱敏后的 `1pctl user-info` 输出贴进 Issue。

**提示「另一个 vhm 任务正在运行」？** 审计、应用、回滚、巡检互斥。等待它结束即可，锁会随进程退出自动释放，不要手动删除锁文件。
