# vhm 使用手册

适用版本：0.4.x。系统要求：Debian 11+ / Ubuntu 20.04+，systemd，root 权限。

## 1. 安装与升级

```bash
sudo git clone https://github.com/OmenTwwnmfm/vaultwarden-1panel-hardening-manager /opt/vaultwarden-1panel-hardening-manager
sudo bash /opt/vaultwarden-1panel-hardening-manager/run.sh
```
- 仓库路径上的每一级目录都必须 root 所有且他人不可写（`run.sh` 会逐级检查），所以放在 `/opt` 下。
- `run.sh` 安装 `/usr/local/bin/vhm`，重复运行即修复。
- 升级：每次启动菜单时检查 GitHub main，有新版本时列出待更新的提交，输入 `yes` 才快进；也可用菜单 `[27]` 手动检查。在 `/etc/vaultwarden-hardening.conf` 中配置：
  - `AUTO_UPDATE="notify"`（默认）：提示后确认；`"apply"`：自动更新（0.3.x 的行为）；`"off"`：不自动检查。
  - `UPDATE_REQUIRE_SIGNED="1"`：只接受 `git verify-commit` 校验通过的提交（需要先在 git 中配置信任的公钥）。
- `run.sh` 同时安装日志轮转配置 `/etc/logrotate.d/vaultwarden-hardening`。
- 移动项目目录后，在新位置重新运行 `run.sh`；进入菜单时会自动把 vhm 的 systemd 单元改到新位置，体检也会提示指向不存在脚本的单元。
- 从 0.1.x 升级：首次进入菜单时自动停用并删除 `vaultwarden-hardening-watch.service/.timer` 与 `/usr/local/lib/vaultwarden-hardening`。旧报告与快照留在 `/var/lib/vaultwarden-hardening/`，不再使用，可手动删除 `reports/` 与 `snapshots/`。

## 2. 路径
| 用途 | 路径 |
|---|---|
| 配置（实例） | `/etc/vaultwarden-hardening.conf`（600） |
| 变更记录 | `/var/lib/vaultwarden-hardening/changes/<时间>-<PID>/` |
| 日志（已脱敏） | `/var/log/vaultwarden-hardening.log` |
| SSH 配置 | `/etc/ssh/sshd_config.d/00-vhm.conf` |
| 2FA PAM | `/etc/pam.d/sshd` 中的 `pam_google_authenticator.so` 行 |
| 2FA 绑定 | `/root/.google_authenticator`（400） |
| Fail2Ban | `/etc/fail2ban/jail.d/vhm-sshd.local` |
| 内核参数 | `/etc/sysctl.d/90-vhm-hardening.conf` |
| Vaultwarden 设置 | `<数据目录>/config.json` |

## 3. 通用规则
- 只读功能（体检、状态、端口一览、用户列表、登录记录）不修改任何文件。
- 修改功能：显示要改什么 → 输入 `yes`（大小写不敏感）→ 保存原文件到变更记录 → 修改 → 校验 → 失败自动恢复。
- vhm 的修改操作互斥，冲突时提示「另一个 vhm 修改操作正在运行」并以 75 退出。
- `[25]` 列出最近 30 条变更和占用空间，可按条回滚。回滚会恢复该次修改涉及的所有文件并重新加载相关服务；如果之后还有改过同一文件的变更，会一并被覆盖，界面会提示。回滚失败会标记为「回滚失败」并保留记录，修复原因后可在 `[25]` 重试，重试前不要删除记录。
- 原理：修改前把要改的文件整份复制到 `changes/<时间>-<PID>/files/`，在 `files.tsv` 记下路径、权限、属主和「修改前是否存在」；1Panel 面板设置另存在 `panel.prev`。回滚时放回副本、删除修改前不存在的文件，再重新加载 SSH、Fail2Ban、内核参数、1Panel 或 Vaultwarden。
- 删除记录：可删除指定序号（如 `3 5 8-12`）、所有「已回滚」的记录，或只保留最近 N 条。删除「已生效」的记录后，那次修改就不能再回滚了（修改本身保留）。
- 自动清理：每次新修改前，删除「最近 50 条以外且超过 90 天」的记录。防锁死保护中、或一小时内创建且未完成的记录不会被删除。记录中含 2FA 密钥文件和 `config.json` 副本，目录权限 `700`。

## 4. SSH

### 4.1 防锁死保护
`[05]` 修改端口、`[06]` 切换 SSH 登录方式、`[07]` 重新绑定或关闭 2FA 时：
1. 写入配置后先执行 `sshd -t`，并用 `sshd -T` 确认生效值确实是期望值（防止被其他配置覆盖）。
2. 重载 SSH 服务（支持 Ubuntu 22.10+ 的 `ssh.socket`），当前会话不会断开。
3. 启动一个 5 分钟的 systemd 定时器。你需要**保持当前窗口**，另开窗口按新方式登录，成功后回来输入 `yes`。
4. 输入其他内容、超时或 vhm 被中断，定时器都会自动回滚。
5. 保护期内机器重启时，常驻的 `vhm-guard-boot.service` 在开机时回滚仍未确认的修改（之后又有改过同一文件的变更时除外）。

VPS 服务商控制台的 VNC 登录不受影响，可作为最后的应急入口。

### 4.2 SSH 登录方式

菜单 [06] 可选择密码登录（不建议）、密钥登录、密码 + 动态口令、密钥 + 动态口令（推荐），也可修改 root 系统密码。

| 模式 | sshd 认证组合 | 说明 |
|---|---|---|
| 密码登录（不建议） | password | 只接受 root 系统密码 |
| 密钥登录 | publickey | 只接受 authorized_keys 中的密钥 |
| 密码 + 动态口令 | keyboard-interactive + PAM | 由 PAM 依次验证系统密码和 TOTP |
| 密钥 + 动态口令（推荐） | publickey,keyboard-interactive | 先验证 SSH 密钥，再验证 TOTP |

- 切换模式前要求确认，并检查 root 是否已有有效密钥或密码。
- 变更后运行 sshd -t 和 sshd -T 验证，重载后进入 5 分钟自动回滚保护。
- 仅 root 使用 PAM 动态口令。绑定流程会在终端显示二维码及手动密钥，验证一次 TOTP 后生成 5 个一次性应急码。
- 前提：root 至少有一个授权密钥（`[04]`）；系统时间已同步（`timedatectl set-ntp true`）。
- 绑定流程：显示二维码 → 用验证器扫码 → 输入一次口令校验 → 显示 5 个应急码（每个只能用一次，请抄下来）。二维码扫不出来时，把终端窗口拉大，或在验证器中选「输入设置密钥」，填入二维码下方显示的密钥。
- 实现：`AuthenticationMethods publickey,keyboard-interactive`，PAM 中注释当前的 `common-auth` 行（`@include common-auth` 或 `auth substack common-auth`）并加入 `auth required pam_google_authenticator.so`（不带 `nullok`）。因为认证组合已强制先通过密钥，`PermitRootLogin` 设为 `yes`；关闭 2FA 后恢复为 `prohibit-password`。
- 影响：其他系统用户（若有）没有动态口令将无法 SSH 登录；1Panel 的「终端」功能通过 SSH 连本机，启用后不可用，「容器终端」不受影响。
- `[07]`：显示绑定二维码（在新手机或第二个验证器上添加同一账号，旧手机继续有效）、重新绑定（换新密钥，旧二维码和应急码全部失效）、查看剩余应急码、关闭 2FA。显示二维码前会提醒确认周围没人看屏幕。

### 4.4 修改端口
1. 检查新端口未被占用，且防火墙已放行（ufw / firewalld 自动检查；未放行时提示到 1Panel →「主机」→「防火墙」放行）。云服务器还要在安全组放行。
2. 先同时监听新旧端口，确认新端口能登录后再关闭旧端口，并同步 Fail2Ban 的端口。

### 4.5 登录密钥与登录记录
- `[04]` 列出 root 授权密钥的指纹与备注，标出当前会话使用的密钥；拒绝删除唯一的密钥或当前会话的密钥。
- `[08]` 统计最近 N 天的成功登录与失败来源 IP，用来决定 Fail2Ban 白名单。

## 5. 防火墙与 Docker

- 菜单 [15] 支持 1Panel iptables 和 UFW 后端，管理允许 / 拒绝、IPv4 / IPv6、TCP / UDP、目标端口、来源 IP/CIDR 和插入顺序。
- 1Panel iptables 模式直接更新 `1PANEL_BASIC` 链，再按 1Panel 自己的保存方式把整条链写入 `1panel_basic.rules`（IPv6 为 `ipv6_1panel_basic.rules`），1Panel 重启后会从这里恢复。UFW 模式通过 `ufw` 命令增删，UFW 自己负责持久化。规则立即生效，刷新 1Panel 防火墙页面即可看到。
- 1Panel iptables 模式显示 `1PANEL_BASIC_BEFORE`、`1PANEL_BASIC`、`1PANEL_BASIC_AFTER` 三条链。vhm 新建和删除规则只操作 `1PANEL_BASIC`，BEFORE / AFTER 是 1Panel 系统链，菜单中只读展示；端口体检按三条链的实际顺序判断放行结果。
- 规则列表每次都从 iptables / UFW 实时读取，vhm 不另存规则清单。在 1Panel 页面新增或删除的规则会直接出现在 `[15]` 中，反过来也一样。
- 防火墙目录从 `1pctl` 的 `BASE_DIR` 推算，默认 `/opt/1panel/firewall`。自定义安装目录识别不到时，在 `/etc/vaultwarden-hardening.conf` 中设置 `PANEL_FIREWALL_DIR`。
- vhm 创建的规则注释为 `vhm:<编号> 备注`。`[15]` 只删除这些规则，其他规则继续在 1Panel 中管理。
- 回滚（`[25]`）只撤销该次变更添加或删除的那一条规则，不会覆盖之后在 1Panel 中做的其他修改。删除过的规则恢复时尽量放回原位置。
- 修改 SSH 或 1Panel 面板端口前会检查该端口是否已放行。若用范围规则或云服务商安全组放行，可在提示后选择跳过。
- Docker 发布端口时流量走 FORWARD 链，不经过 INPUT 放行链。容器端口绑定 0.0.0.0 时，外网可能绕过反代直接访问。体检会检测 1Panel v2 Docker 端口访问控制并提示到 1Panel 应用参数关闭外部访问。

## 5.1 1Panel 面板

全部通过 `1pctl`（按 1Panel v2.5 的子命令）完成：

| 菜单 | 功能 | 回滚 |
|---|---|---|
| `[09]` | 版本、服务、端口、安全入口、协议、监听方式、面板端口放行范围、面板用户 | 只读 |
| `[10]` | `1pctl update port`：检查占用和放行 → 修改 → 等待新端口启动 | 可以 |
| `[11]` | `1pctl update username / password`，可先生成随机密码 | 不可以 |
| `[12]` | `1pctl listen-ip ipv4 / ipv6` 并重启面板 | 可以 |
| `[13]` | 启动 / 停止 / 重启 `1panel-core`、`1panel-agent` | — |
| `[14]` | `1pctl reset entrance / ips / domain / https / mfa / passkey`，必须输入项目名确认 | 不可以 |

应急重置会降低面板安全性，只在被面板挡在外面时使用；恢复访问后请立即在 1Panel →「面板设置」→「安全」中重新设置。

## 6. Fail2Ban
- `[16]` 未安装时自动安装；配置失败次数、统计窗口、封禁时长、白名单（默认填入当前连接 IP）。日志后端自动选择（没有 `/var/log/auth.log` 时用 systemd journal）。
- 配置先经 `fail2ban-client -t` 检查，启动失败自动恢复。
- 如果 1Panel「Fail2ban」页面也启用了 sshd，会重复封禁，建议只保留一份。
- SSH 端口自动同步：配置成功后启用 `vhm-ssh-port-sync.path` 和 `vhm-ssh-port-sync.timer`。修改 `/etc/ssh/sshd_config` 或 `/etc/ssh/sshd_config.d/` 中任意文件时立即触发，定时器另每 5 分钟用 `sshd -T` 核对一次。端口变化后更新 `/etc/fail2ban/jail.d/vhm-sshd.local` 的 `port` 并重载 Fail2Ban，同步失败时恢复原 jail。只维护这一个文件，不动 1Panel 或系统自带的 jail。
- `[17]` 查看状态与封禁列表，输入 IP 解封。

## 7. Vaultwarden

### 7.1 实例识别
扫描挂载了 `/data` 且镜像名含 `vaultwarden` 的容器，以 `/data` 的主机路径作为实例身份。已安装 vbm 时复用 `/etc/vaultwarden-backup.conf` 的 `VW_DATA_DIR`。0 个或多个候选都会停止，不猜测；多实例时在 `/etc/vaultwarden-hardening.conf` 填写 `VW_DATA_DIR`。1Panel 重建应用导致容器名变化时，按数据目录自动重新匹配。

### 7.2 设置写在哪里
所有修改写入数据目录的 `config.json`（与在 `/admin` 页面保存的效果相同）。它优先于 1Panel 应用参数（环境变量），且 1Panel 升级或重建不会覆盖。`[18]` 会显示每项的实际生效值和来源。

### 7.3 修改流程
1. 调用 vbm 完整备份（会短暂停止 Vaultwarden），本地校验、服务恢复、远端核验全部通过才继续；vbm 正在执行定时备份时直接放弃。未安装 vbm 时需额外确认。
2. 持有 vbm 的锁，避免定时备份在此期间启动。
3. 保存原 `config.json` → 写入（原子替换，600）→ 重启容器 → 等待健康检查（最多 120 秒）。
4. 失败自动恢复原 `config.json` 并再次重启。

### 7.4 功能
- `[19]` 开放注册、邀请注册。
- `[20]` 后台 ADMIN：开启时生成随机密码（只显示一次）或自己输入，`config.json` 只保存 argon2id 哈希（m=19456, t=2, p=1）；关闭时写入空令牌，同时覆盖 1Panel 参数中的 `ADMIN_TOKEN`。建议在 1Panel 网站反代中限制 `/admin` 的来源 IP。
- `[21]` 用户列表：邮箱、注册时间、最近活动、是否开启两步验证、是否禁用。只读打开 SQLite，不支持外部数据库；删除或禁用用户请在 `/admin` 中操作。
- `[22]` 安全选项：密码提示、登录页显示提示、Send、紧急访问、可创建组织的用户、图标服务；一键推荐（Send 保持不变）。

## 8. 系统加固
- `[23]` 自动安全更新：安装并启用 `unattended-upgrades`，写入 `/etc/apt/apt.conf.d/20auto-upgrades`。只装系统安全更新，不升级容器，不自动重启。
- `[24]` 内核网络参数：SYN cookies、拒绝 ICMP 重定向与源路由、反向路径过滤（宽松模式 2，兼容 Docker）、忽略广播 ping。不修改 `ip_forward`。回滚时恢复修改前的运行时值。

## 9. 体检项
| 类别 | 检查 |
|---|---|
| 端口 | 主机防火墙是否启用；哪些端口监听在所有地址上 |
| Docker | 容器端口是否发布在所有地址上（并实测） |
| SSH | 端口、密码登录、2FA、root 直接登录、空密码、`MaxAuthTries`、`LoginGraceTime`、`X11Forwarding`、`authorized_keys` 权限、时间同步 |
| Fail2Ban | 是否安装、运行、有 sshd 防护、当前封禁数 |
| 系统 | root 以外 UID 0 账户、sudo 用户、自动安全更新、内核参数、是否需要重启、vhm 后台服务指向的脚本是否存在 |
| 1Panel | 面板端口、安全入口（MFA 需人工确认） |
| Vaultwarden | 开放注册、后台状态与令牌类型、DOMAIN 是否 https、数据目录权限、vbm 最近一次备份 |

体检只做本机检查，无法证明公网实际可达性；云服务器还要核对服务商安全组。

## 10. 命令行
`sudo vhm` 进入菜单。只读子命令：`checkup`、`ports`、`ssh-status`、`vw-status`、`vw-users`、`changes`、`diagnose`、`deps`、`version`；`rollback <变更ID>` 回滚。修改操作只在菜单中提供。

退出码：`0` 成功 · `1` 失败/取消 · `2` 实例无法确定 · `75` 另一个 vhm 修改操作正在运行。

## 11. 常见问题
**2FA 启用后登录被拒？** 先看时间是否同步；用应急码登录；仍不行就在保护时间内什么都不做，等待自动回滚，或用 VNC 登录后执行 `vhm rollback <变更ID>`（`vhm changes` 查看 ID）。

**1Panel「SSH 管理」显示的值不对？** vhm 的配置在 `sshd_config.d/00-vhm.conf`，优先于主配置。请以 `[03]` 显示的生效值为准，SSH 只用 vhm 管理。

**改了 1Panel 应用参数却不生效？** `config.json` 中的同名设置优先。用 `[18]` 查看来源，在 vhm 中修改即可。

**提示「发现多个候选实例」？** 在 `/etc/vaultwarden-hardening.conf` 填写 `VW_DATA_DIR`，再运行 `[01]`。

## 12. VNC 手动恢复
vhm 本身也无法运行、或 SSH 已经登不进去时，通过服务商控制台的 VNC 以 root 登录，按需执行：

1. 先试 vhm：`vhm changes` 查看变更 ID，`vhm rollback <变更ID>` 回滚。
2. 撤销 vhm 的 SSH 设置：
   ```bash
   mv /etc/ssh/sshd_config.d/00-vhm.conf /root/00-vhm.conf.bak
   rm -f /etc/systemd/system/ssh.socket.d/00-vhm.conf
   sshd -t && systemctl daemon-reload && { systemctl restart ssh.socket ssh 2>/dev/null || systemctl restart ssh || systemctl restart sshd; }
   ```
3. 恢复 PAM：vhm 只调整 `/etc/pam.d/sshd` 中的 `common-auth` 与 `pam_google_authenticator.so` 两行。把被注释为 `#vhm# @include common-auth` 的行恢复为 `@include common-auth`，并删除 `auth required pam_google_authenticator.so` 行；或从 `/var/lib/vaultwarden-hardening/changes/<ID>/files/` 中取回修改前的副本（`files.tsv` 第 5 列是原路径）。
4. 清除 vhm 添加的防火墙规则（1Panel iptables）：`iptables -S 1PANEL_BASIC | grep 'vhm:'` 查看，把对应行的 `-A` 改为 `-D` 执行删除，然后在 1Panel 防火墙页面保存一次以写入持久文件；UFW：`ufw status numbered` 后 `ufw delete <编号>`。
5. 停用 vhm 后台服务：`systemctl disable --now vhm-ssh-port-sync.path vhm-ssh-port-sync.timer vhm-guard-boot.service`。

## 13. 改用普通用户登录
长期更稳妥的做法是用普通 sudo 用户登录，禁止 root 直接登录。vhm 目前的 2FA 只为 root 绑定，可以手动完成：

1. `adduser admin && usermod -aG sudo admin`，把公钥写入 `/home/admin/.ssh/authorized_keys`（目录 700、文件 600，属主 admin）。
2. 另开窗口确认 `ssh admin@服务器` 能登录且 `sudo -i` 可用。
3. 需要动态口令时，以 admin 身份运行 `google-authenticator` 绑定。
4. 在 `/etc/ssh/sshd_config.d/10-local.conf` 中写入 `PermitRootLogin no`。注意 vhm 的 `00-vhm.conf` 优先，其中若有 `PermitRootLogin` 需要一并调整；修改前保持当前窗口，`sshd -t` 通过后再重载，并另开窗口验证。
